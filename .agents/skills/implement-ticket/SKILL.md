# Implement Ticket（ML AOS）

## 执行顺序

1. 读取已确认产品规格与 Tickets，只实现当前范围。
2. 先检查仓库约定、现有实现和相关测试，再做最小且完整的代码修改。
3. 运行与改动相关的类型检查、测试和构建，先解决基础验证失败。
4. 若配置了浏览器验收 Skill（如 `agent-browser`），按该 Skill 做真实页面验收；失败则修复后重跑。
5. 全部通过后给出：实现摘要、验证命令、剩余风险。流水线会推进到测试 / 审查阶段。

## 边界

- 不擅自扩展产品范围，不自动部署，不自动创建 Pull Request（除非任务明确要求）。
- 无法启动应用、缺少账号或外部依赖不可用时，停止并明确报告阻塞。
- 不要尝试直接联系 CEO 助理；结果由 ML AOS 交回调度或推进流水线。
