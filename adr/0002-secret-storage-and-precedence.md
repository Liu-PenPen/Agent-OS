# ADR 0002：密钥读取优先级、落盘与展示

## Status

Accepted（设计访谈 round 2 确认）

## Context

双通道（ADR 0001）确定后，必须明确：环境变量与设置页存档冲突时谁生效、安装版是否还认仓库根 `.env`、token 如何落盘与在 UI 中展示、以及维护者现有根 `.env` 是否要强制搬家。

## Decision

1. **优先级**：`process.env`（含启动前已注入的系统环境变量，以及开发时根目录 `.env` 载入结果）**高于** `dataDir` 中设置页存档。仅当某键在环境中未设置时，才回落到存档。
2. **安装版**：文档约定 `.env` 文件通道面向「克隆源码 + pnpm」用户；Tauri 安装包用户以设置页 → `dataDir` 为主，不承诺读取某个「仓库根 `.env`」。
3. **落盘**：设置页保存的密钥以**明文 JSON** 写在 `dataDir`（与现有 settings / 项目 JSON 同一信任边界：本机登录用户可读）。第一期不上钥匙串 / 应用层加密。
4. **迁移**：不强制导入或废弃根 `.env`。开发者现有工作流继续有效；设置页是开源与安装用户的主入口。
5. **展示**：token 在设置页始终遮罩（如 `••••` + 可选末 4 位）；修改即整段重填。企业 ID、用户 ID 可明文编辑。

## Consequences

- 实现上需要统一的「解析凭证」函数：先读 env，再读 `dataDir` 存档，供 Gitee client 与设置 API 共用。
- 设置「保存」时若 token 输入框为空（用户未改遮罩字段），应表示**保留原存档**，而不是清空；显式「清除凭证」另议。
- README / `.env.example` 需写清优先级与安装版路径，避免用户以为改了设置页却被 shell 里残留的 env 盖住。
