## 1. 产品定位

ML AOS 是 miluo 的 **本地多 Agent 协作工作台**（Tauri 桌面应用）。

- **对用户**: 在桌面内用「话题工作区 + 群聊」驱动多 Bot（CEO / 产品 / 开发 / 测试 / 评审）协作，不再依赖飞书。
- **对现有 agent-os**: **能力复刻、代码隔离**。不修改、不运行现有 `agent-os` 进程；仅参考其设计与配置格式（如 `bots.json`、协作状态机、CLI 适配思路）。
- **关系约定**:
  - `agent-os`（现仓）= 飞书版运行时
  - **ML AOS** = 独立桌面复刻版

副标题可用：**ML AOS · miluo Agent OS 桌面工作台**

## 3. 总体架构

```text
┌─────────────────────────────────────────────────────────────┐
│  Tauri Shell (Rust)                                          │
│  窗口 · 托盘 · 本地路径选择 · 进程保活 · 系统通知               │
└───────────────────────────┬─────────────────────────────────┘
                            │ IPC
┌───────────────────────────▼─────────────────────────────────┐
│  Frontend (React) —— TabTin 式三栏工作台                      │
│  工作区/话题 · 群聊时间线 · 任务/澄清/HITL 侧栏 · 设置         │
└───────────────────────────┬─────────────────────────────────┘
                            │ 本地 API / 事件流 (WS 或 IPC)
┌───────────────────────────▼─────────────────────────────────┐
│  Desktop Runtime（新写，能力对齐 agent-os）                    │
│  Bot Registry · Topic/Session · Collaboration Pipeline       │
│  Clarification/HITL · Config Store · CLI Adapters            │
└───────────────────────────┬─────────────────────────────────┘
                            │ spawn（无 shell 优先，对齐 Windows 教训）
┌───────────────────────────▼─────────────────────────────────┐
│  Claude Code / Codex CLI（用户本机配置，密钥不进仓库）           │
└─────────────────────────────────────────────────────────────┘
```

### 3.1 分层职责

1. **Tauri Shell**: 原生窗口与系统能力；拉起/监控 Runtime；不承载业务编排。
2. **React UI**: 唯一主界面；消息、卡片、流水线可视化。
3. **Desktop Runtime**: 会话、派发、状态机、CLI 适配；持久化到本地（SQLite 或 JSON 目录，实现阶段再定）。
4. **CLI 引擎**: 与现网相同能力面（Claude / Codex）；密钥走用户级配置。

### 3.2 明确不做（一期）

- 飞书 IM / 卡片 / Webhook / 云文档同步
- 运行或依赖现有 agent-os 进程
- Eyes 视觉回归完整闭环、定时任务调度（仅导航占位）

## 5. 首页信息架构（主界面）

布局参考 TabTin 工作台：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶栏：ML AOS · 全局搜索 · Bot 状态 · 设置                      │
├──────────┬─────────────────────────────┬─────────────────────┤
│ 左栏     │ 中栏（主）                    │ 右栏                │
│ 工作区   │ 话题标题 + 成员/Bot 头像       │ 本话题任务           │
│ 话题列表 │ 消息时间线（人 / 多 Bot）      │ 流水线阶段           │
│ 搜索     │ 内嵌澄清卡 / 审批卡            │ 待你确认             │
│ 新建话题 │ 底部输入：@Bot · 发送 · 中止   │ 工作目录 / Git / 引擎 │
└──────────┴─────────────────────────────┴─────────────────────┘
```

右栏应展示当前工作区的 **localPath** 与 **gitUrl**（可截断），并提供「更改目录 / 编辑 Git」快捷入口（打开工作区设置）。

### 5.1 首页必须可见的信息

- 当前工作区与话题列表（含进行中标记）
- 活跃话题的完整消息流
- 至少一个「待确认」入口（澄清或审批）在右栏或内嵌卡
- 输入区可 @ Bot
- 品牌标识：**ML AOS**（顶栏左）
- 当前工作区工作目录与 Git 摘要（右栏）

### 5.2 视觉方向（设计约束）

- 主锚：TabTin 式多栏协作工作台，而非 IDE、非纯聊天页
- 借 DeepSeek/Cursor：干净输入区、流式气泡、工具调用可折叠
- 避免：默认紫渐变营销风、报纸多栏、奶油衬线 Terracotta 套路
- 主题：**深色 / 浅色 / 跟随系统**；默认深色；CSS 变量换肤；设置页 + 顶栏快捷切换
- 建议：中性专业工作台色板；品牌色点缀「ML」标识（详见 design-system）

## 6. 配置与数据（一期约定）

### 6.1 领域模型（配置相关）

```text
Workspace
  id, name
  gitUrl?: string          // 如 https://github.com/org/repo.git
  localPath: string        // 本机工作目录（必填；可先选本地再填 git）
  topics: Topic[]

BotConfig（全局，非每工作区一份）
  id, name, role, defaultEngine, system/instructions…
  // 字段语义参考 agent-os bots.json，存储在 ML AOS 本地

AppSettings
  theme: "dark" | "light" | "system"   // 默认 dark；跟随系统时读 OS
  defaultEngine, dataDir, notifications…
```

### 6.2 行为约定

- **Bot 配置**：设置 → Bots；可增删改；聊天 `@` 与派发只使用已启用 Bot。
- **工作目录**：创建/编辑工作区时必选 `localPath`（系统文件夹对话框）；右栏只读展示 + 快捷编辑。
- **Git 地址**：工作区可选填 `gitUrl`；一期支持「保存地址」+「若本地为空则可 Clone 到 localPath」（需本机 git）；不做完整 Git GUI（commit/PR 等二期可选）。
- **切换 localPath**：须清空/隔离该工作区下话题的旧 CLI session，避免上下文串目录。
- **主题**：`dark` / `light` / `system`；持久化；CSS 变量驱动全应用；App Settings 提供分段控件，顶栏可快捷切换（不改变「跟随系统」时的偏好语义：快捷切换可写入显式 dark/light）。
- Bot / 工作区配置落在 ML AOS 本地目录，**不读写**现有 agent-os 仓库文件。
- 凭证：不进 git；Claude/Codex 用用户级配置；Git 凭据走系统/credential helper，应用不存明文 token（一期）。

## 7. 验收标准（一期）

1. 独立仓库可启动桌面窗口，顶栏显示 **ML AOS**。
2. 可在设置中配置至少一个 Bot，并在话题中 @ 该 Bot 发消息（真 CLI 或 mock 在实现计划中写明）。
3. 可创建工作区并指定 **localPath**；右栏可见该路径。
4. 可为工作区配置 **gitUrl**；有本地 git 时可完成一次 Clone 到 localPath（或文档说明跳过条件）。
5. 可触发一次跨 Bot 派发，右栏可见流水线阶段变化。
6. 可完成一次澄清卡片交互，结果写回会话。
7. 可在设置中切换 **深色 / 浅色 / 跟随系统**，界面即时换肤并持久化。
8. 现有 `agent-os` 仓库无功能代码被修改。

## 8. 实现顺序（概要）

1. 脚手架：Tauri + React + Runtime 骨架  
2. 首页三栏静态 UI（按已批准设计稿）  
3. 工作区模型：localPath + gitUrl；新建/编辑工作区表单  
4. Bot 配置页（CRUD）  
5. 本地会话与消息模型  
6. 单 Bot CLI 连通  
7. 多 Bot @ 与派发状态机  
8. 澄清 / HITL 卡片  
9. （可选）git clone 到 localPath  

详细任务拆解见后续 implementation plan（规格批准后编写）。
